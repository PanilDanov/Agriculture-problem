# Контракт данных для регионального прогноза урожайности

Версия 1.0. ML принимает одну культуру, один сезон сбора и один административный регион. Интерфейс работает с `maize` и `wheat`. Оценка в т/га относится к административной единице и помечается `spatial_level: "administrative_region"`. Для урожайности отдельного поля валидация отсутствует.

## Схема A · Raw Environmental Input

[JSON Schema](../src/yield_prediction/schemas/raw_environmental_input.schema.json) · [Пример структуры](examples/raw_synthetic.json) · [Пример отказа на годовых данных](examples/annual_unsupported.json).

| Поле | Требование |
| --- | --- |
| `schema_version`, `as_of`, `harvest_year` | Обязательные. Версия `"1.0"`, фактическая дата среза данных в формате YYYY-MM-DD, год окончания целевого сезона. |
| `region` | Обязательные `aggregation`, `match`, источник и версия границ. Для `cybench_verified` обязательны `country_code` и точный `adm_id`. При `unmapped` код страны и ID могут отсутствовать. Широта и долгота опциональны, это координаты центроида региона в WGS84. |
| `calendar` | Обязательные источник и список `seasons`. Для каждого года нужны `start`, `end`, `available_on`. Одна запись на год, границы включительны, сезон может начаться в предыдущем году. |
| `weather` | Обязательные продукт, версия, `time_standard`, единицы всех параметров, ежедневные наблюдения. Принимаются `AgERA5` 2.0 и `CY-Bench AgERA5` 1.10, агрегированные по региону и маске культуры с документированными локальными сутками `LST`. |
| `weather.observations[]` | `date`, фактическая `available_on`, `tmin`, `tavg`, `tmax`, `prec`, `rad`, `et0`, `vpd`, `cwb`. Пропуск измерения передаётся как JSON `null`. Дубли дат и дата публикации раньше наблюдения приводят к отказу. |
| `soil` | Опционально. Источник и версия, доступность `available_on`. Источник `CY-Bench WISE` поддерживает `awc` с единицей `CY-Bench WISE` и `bulk_density` в кг/дм³. Для другого источника эти входы остаются пустыми. |

В каждом блоке источника можно передать `source_reference` и `artifact_sha256`. Срез должен достигать даты прогноза. Для `pre_season` и `cold_start_pre_season` это календарный день перед началом сезона, для `mid_season` и `mid_season_v2` — `start + floor((end − start) / 2)` суток. Текущий календарь должен быть известен к предсезонной дате. Пересекающиеся сезоны отклоняются.

Историческая климатология использует до пяти последних завершённых пригодных сезонов за семь предыдущих годов сбора. Нужно минимум два сезона. Границы их календарей должны быть известны до предсезонной даты. Используются дни, которым на дату прогноза исполнилось не менее 14 дней и для которых `available_on` уже наступила. Климатология фиксируется предсезонным срезом и при прогнозе середины сезона. Текущая погода ограничена от начала сезона до середины минус 14 суток включительно. Полная запись содержит восемь погодных значений. Для каждого окна нужно ≥95% полных дней, для Mid-season также нужно ≥10 ожидаемых дней. Поздние наблюдения исключаются и подсчитываются в диагностике. Наблюдения с неизвестной датой доступности нельзя передавать как заведомо доступные.

## Схема B · Model Features

[JSON Schema](../src/yield_prediction/schemas/model_features.schema.json) · [преобразованный пример](examples/model_features_synthetic.json) · [реальные примеры CY-Bench](../artifacts/examples) · [формулы и единицы](feature_mapping.md).

Для работы со всеми экспериментальными кандидатами установите пакет из каталога `yield_prediction` командой `python -m pip install ".[candidates]"`.

Обязательны `country_code`, сезонные даты, год, длина сезона, все исторические агрегаты, число исторических сезонов и `climate_through`. `adm_id` обязателен для стандартных режимов, cold-start допускает его отсутствие. При неизвестной стране cold-start использует `ZZ`, который остаётся метаданными. Для Mid-season добавляются все поля `mid_*`, дата последнего принятого наблюдения и доля покрытия. `awc`, `bulk_density` и координаты опциональны и могут быть `null`. История урожайности прочитывается из замороженного артефакта по проверенному ключу. В схеме нет входа для меток урожайности.

```python
from yield_prediction import build_model_features, predict_yield

prepared = build_model_features(environment, "maize", "pre_season")
if prepared["status"] == "ready":
    result = predict_yield(prepared["features"], "maize", prepared["recommended_mode"])
else:
    diagnostics = prepared["diagnostics"]
```

Результат адаптера содержит статус `ready` или `rejected`, признаки или `null`, исходный и рекомендуемый режим, дату прогноза, покрытие и список диагностик, если доступны. `ready` для cold-start означает пригодный формат и возможность экспериментального расчёта. При запросе Mid-season без проверенной региональной истории адаптер возвращает отказ и предлагает сформировать отдельный предсезонный запрос. При недостаточной погоде возвращается отказ с диагностикой. Отсутствие влажности почвы не влияет на текущие модели. При отсутствии совместимой статической почвы используется предусмотренная импутация. Годовой CSV, точечные данные, ошибочные единицы, пропуск дат и недостаточное покрытие дают диагностический отказ.

## Пространственная привязка

1. Запрашивающий сервис нормализует границу в WGS84 и пересекает её с полигонами административных единиц соответствующего уровня статистики урожайности. Для точки используют point-in-polygon с обнаружением неоднозначности, для полигона сохраняют доли пересечения. Пограничные и многорегиональные поля требуют явного выбора или отдельных региональных расчётов.
2. Для существующих стран используйте полигоны CY-Bench 1.10 и их ID. Для нового региона допустимы официальные границы уровня, публикующего урожайность, с фиксированной версией. Переход между версиями требует таблицы соответствия или подтверждённого пространственного пересечения. Natural Earth Admin 0 годится для предварительного определения страны. Одной границы страны недостаточно для выбора NUTS, округа, провинции или муниципалитета. [Полигоны CY-Bench](https://zenodo.org/records/17279151).
3. Для погодных рядов агрегируйте узлы AgERA5 по той же административной геометрии и площадям выращивания культуры. Версия маски, веса, геометрия и конвенция суток должны храниться вместе с данными источника. Погода одной точки, даже если точку удалось сопоставить региону, не удовлетворяет контракту.
4. При неизвестном CY-Bench ID передайте `unmapped` и верифицируемый источник соответствующей административной геометрии. Если региональная агрегация возможна, адаптер предложит cold-start. При наличии только геометрии поля или точки вернёт ограничение. Сам адаптер принимает готовую привязку, а доказательства пересечения хранит вызывающий сервис.

## Инструкция для Data Engineer

1. Сохраните дневной экспорт рядом с годовым. Передавайте ISO-даты, время суток, исходные и нормализованные единицы, версию продукта, дату первого доступного релиза и ссылки/хеши исходных выгрузок. Время скачивания текущей ревизии не доказывает её историческую доступность.
2. Для прогноза урожайности добавьте отдельный региональный поток AgERA5/CY-Bench. Экспортируйте `Tmin/Tavg/Tmax`, осадки, радиацию, reference ET₀, VPD при Tmax и CWB. NASA POWER и результаты полевого водного расчёта могут оставаться в действующих сценариях оценки поля. Для замены продукта требуется парная проверка на общих регионах и сезонах.
3. Экспортируйте календарь выбранного производственного сезона для каждого года, включая годы с переходом через 31 декабря. Отличайте дату сбора от периода отчётности. Для прогнозов с живым горизонтом добавьте архив публикации урожайности. Настоящее предположение о выпуске меток 1 июля следующего года заменяется фактическими датами после сбора данных.
4. Почвенные признаки поставляйте с глубиной, единицей и источником. Объёмная влажность, pH, SOC и гранулометрия не заменяют `awc` или `bulk_density`. Если WISE несопоставим или отсутствует, оставьте его входы пустыми.
5. Сохраняйте результаты проверки покрытия и качество связки региона с геометрией. Для расширения на полевой уровень подготовьте фактическую урожайность поля, управленческие признаки и отдельную полевую валидацию. Прогноз для холодного старта пока предназначен для пилота. [Текущий полевой сбор](../../agronomy/field-data.md) · [Контракт анализа поля](../../agronomy/analysis-api.md).
