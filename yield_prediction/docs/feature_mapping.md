# Соответствие полевых и региональных признаков

Исходный CSV Data Engineer содержит годовые агрегаты одной точки 42.0, −93.5. `data_pipeline.py` уже получает дневные значения NASA POWER AG/LST во внутреннюю таблицу, а на выходе сохраняет годовой CSV, покрытие и метаданные. Текущий `OUTPUT_COLUMNS` исключает `extreme_temperature_days`. Полевой сбор из `agronomy` отдельно отдаёт дневные записи, включая давление, ветер и точку росы. Модель обучалась на AgERA5 с шагом 0,1° после агрегации по регионам и маске культуры. Пространственные и временные масштабы NASA POWER зависят от продукта, его точечная выборка представляет ячейку сетки. [NASA POWER](https://power.larc.nasa.gov/docs/services/api/temporal/daily/) · [Copernicus AgERA5](https://cds.climate.copernicus.eu/datasets/sis-agrometeorological-indicators?tab=overview) · [CY-Bench 1.10](https://zenodo.org/records/17279151).

## Календарь, пространственный ключ и почва

| ML-поле | Тип и единица | Годовой CSV | Доступность в текущем сборе и необходимое изменение |
| --- | --- | --- | --- |
| `harvest_year` | int, год сбора | `year` — календарный год CSV | Взять год окончания конкретного сезона, согласовать с годом урожайности. |
| `season_start`, `season_end` | ISO-даты | Нет | Полевой сервис возвращает календарные кандидаты из FAO, Sacks, GGCMI. Поставить выбранные даты и `available_on` для текущего и прошлых региональных сезонов. |
| `season_days` | int, суток | Нет | `end − start + 1` по календарю. |
| `country_code` | string, код CY-Bench | Нет | Сопоставить регион с поддерживаемым кодом. Natural Earth Admin 0 даёт кандидат страны. |
| `adm_id` | string, ID региона | Нет | Сопоставить с версией границ CY-Bench и уровнем статистики урожайности. |
| `latitude`, `longitude` | float, градусы WGS84 | Координаты в имени файла | Передавать центроид региона, координаты поля хранить отдельно. |
| `climate_seasons`, `climate_through` | int и ISO-дата | Нет | Число покрытых прошлых сезонов и последняя принятая дата наблюдения. Подать дневную историю и календари за семь лет. |
| `mid_weather_through`, `mid_weather_coverage` | ISO-дата и float 0–1 | Нет | Дата последней полной записи и число полных дней / длина окна текущего сезона после отсечения. |
| `awc` | float, шкала WISE из release CY-Bench | Нет | Поле WISE по агрегации CY-Bench. Полевые SoilGrids содержат водоудержание на разных давлениях по глубинам. Разность водоудержания может характеризовать доступную воду на слое, но требует методики глубины, давления и отдельной калибровки. |
| `bulk_density` | float, кг/дм³ | Нет | WISE в региональном масштабе. SoilGrids `bdod` допускает перевод cg/см³ в кг/дм³ делением на 100, после чего нужен сопоставимый слой и проверка между продуктами. |
| `regional_median_t_ha`, `regional_recent_t_ha`, `regional_history_count` | float т/га, float т/га, int | Нет | Региональные метки с годом сбора и датой публикации нужны для обновления моделей. Признаки внутри пакета вычисляются из замороженной истории, cold-start обходится без них. |

Исходные pH, SOC, текстура, RH2M, SFMC и RZMC не входят в текущую модель. SOC в г/кг можно перевести в массовые проценты делением на 10. Это преобразование не создаёт AWC. [Единицы SoilGrids](https://docs.isric.org/globaldata/soilgrids/SoilGrids_faqs_01.html).

## Погодные признаки

Каждая строка с суффиксом ниже соответствует двум полям `climate_<суффикс>` и `mid_<суффикс>`. Все они числовые. Пространственная опора — административный регион с crop-mask AgERA5. Входное разрешение — ежедневное. Для `climate_` сначала применяется формула внутри каждого завершённого исторического сезона, затем берётся среднее по сезонам. Для `mid_` формула применяется к текущему окну от начала сезона по отсечение середины минус 14 дней.

| Суффикс | Формула и единица | Сопоставление с годовым CSV и NASA POWER | Что вывести для ML |
| --- | --- | --- | --- |
| `temperature_c` | mean дневных Tavg, °C | `average_air_temperature_c`, `T2M` | Дневной AgERA5 Tavg, K − 273,15 при подаче в K |
| `min_temperature_c` | min дневных Tmin, °C | `min_air_temperature_c`, `T2M_MIN` | Дневной AgERA5 Tmin |
| `max_temperature_c` | max дневных Tmax, °C | `max_air_temperature_c`, `T2M_MAX` | Дневной AgERA5 Tmax |
| `temperature_sd_c` | population SD дневных Tavg, °C | Из годовой средней не вычисляется, из датированного `T2M` вычисляется | Дневной AgERA5 Tavg |
| `precipitation_mm` | сумма дневных осадков, мм | `precipitation_mm`, дневной `PRECTOTCORR` | AgERA5 precipitation flux в мм/сут |
| `precipitation_mm_day` | сумма / полные дни, мм/сут | Годовое деление не даёт сезонного результата | Те же дневные осадки |
| `radiation_mj_m2_day` | mean дневной радиации, МДж/м²/сут | `solar_radiation_mj_m2_day`, `ALLSKY_SFC_SW_DWN` | AgERA5 J/м²/сут ÷ 10⁶, либо подача явно в MJ |
| `et0_mm` | сумма дневного grass-reference ET₀, мм | В CSV нет. Полевой API рассчитывает FAO-56 из нескольких POWER-параметров | AgERA5 reference ET₀, сравнить отдельно с полевым расчётом |
| `vpd_kpa` | mean дневного VPD при Tmax, кПа | В CSV нет. Средней RH и средней T недостаточно | AgERA5 VPD при Tmax, hPa ÷ 10 |
| `water_balance_mm` | сумма дневных precip − ET₀, мм | Годового ET₀ нет, `waterScreenMm` учитывает иной расчёт | Дневной CWB из совместимых осадков и ET₀ |
| `hot_days` | число Tmax ≥35°C | Был общий годовой счётчик, из дневных Tmax можно восстановить | AgERA5 Tmax |
| `frost_days` | число Tmin <0°C | Был общий годовой счётчик, из дневных Tmin можно восстановить | AgERA5 Tmin |
| `dry_days` | число дней с осадками <1 мм | Нет, из дневных осадков рассчитывается | AgERA5 precipitation flux |
| `climate_precipitation_sd_mm` | выборочное SD сезонных сумм осадков, мм | Годовые суммы задают другие интервалы | Дневные осадки за ≥2 завершённых сезона |
| `climate_temperature_interannual_sd_c` | выборочное SD сезонных средних Tavg, °C | Годовые средние задают другие интервалы | Дневной Tavg за ≥2 завершённых сезона |

Из исходного CSV непосредственно пригодны только наблюдения для проверки единиц и качества. Для численного прогноза сейчас не хватает подтверждённой геометрии и ID региона, календаря по годам, доступности по датам, агрегированного AgERA5, полного набора ET₀/VPD/CWB и совместимых WISE-оценок. WISE-оценки опциональны в интерфейсе. [Контракт и очередность изменений](data_engineer_contract.md).
